# Source

- `menu.s` - the title menu routine (SH-3). Called every frame instead of the "PRESS 1P OR 2P START" text draw; reads P1 input from `0x0C05C474`, draws ORIGINAL ARCADE / ARRANGE MODE with the game's own text routine (`0x0C05CBD8`) and the colour word at `0x0C05CB50`.
- `patch.s` - patcher (runs once at boot from RAM, installs the hook at `0x0C092128` / literal `0x0C092138`, then starts the game at `0x0C002A30`), includes `menu.s`.
- `hyper.s` - Hyper Bomb: in ARRANGE MODE the bomb's blast spawner (literal `0x0C06BC80` -> `0x0C10EB90`) is replaced by the game's bullet cancel `0x0C06E620` with gem type 1 (big gems); the bombing flag (word +12 of the bomb-stock object) is cleared so gems can spawn, and the bomb invulnerability (literal `0x0C06BC88` -> `0x0C068AA0`) is set to 120 frames. The voice is played by the caller and is kept.
- `chain.s` - chain cancel: a jump at the start of the enemy-remove routine `0x0C0764C0` (literal at `0x0C07650C`) runs `enemy_kill` in ARRANGE MODE; enemy position is in the actor at enemy+0x900 (+8 x, +0xC y, 16.16). Bullets (list at manager `@0x0C27DE48` + 0x48440, +0x14/+0x18 position) within 48 px are put into the game's cancel state with gem type 0 (small), queued (0x0C7BF000, max 512) and each queued bullet cancels others within 32 px.
- `meter.s` - hyper meter: `gem_hook` replaces the gem-collect call `0x0C06B730` (literal `0x0C0951AC`; r4 = bomb-stock object, P1 = `0x0C383A1C`, r5 = item type 0 small / 1 big), value at `0x0C7BFF18`, full = extra bomb via `0x0C06BBD0` plus a pending flag (`0x0C7BFF28`, cleared on the title) that `player_hook` turns into `0x0C06E620(3, 0)` on the next frame (every bullet becomes a big gem). `player_hook` replaces the per-frame player update call `0x0C067B60` (literal `0x0C069B64`) and queues `meter_draw` in the game's draw list (`0x0C05C394`, priority 510; bucket 511 is never drawn). `meter_draw` appends blitter sprites at `@0x0C05100C`: one 2P bomb icon (4 layers, tiles `0x08E000F0`, `0x08C000F0`, `0x071000E0`, `0x070000F0`) per 2000 points in the boxes from x=133 in steps of 17, the digits use the score font (tile `0x04F80080 + 8*digit`). Positions must add the framebuffer origin at `0x0C051004`/`0x0C051008` (double-buffered). `meter_draw` subtracts the game's HUD slide (`0x0C38333C` / 4 pixels; 0 in play, +6 per frame when the stage ends) from the y origin so the icons follow the bottom bar, and stops at 96. `player_hook` skips the drawing while the player state word (`0x0C3833A8`, player+0x10) is 0, which is the score tally and game over (18 while playing).
- God Mode only: `menu.s` sets the Mode Select timer start (`mov #3,r7` at `0x0C102560`) in ARRANGE MODE, and `mode_set` in `hyper.s` (literal `0x0C10458C` -> setter `0x0C068520`) forces mode 2 (God). Mode is player+0x50 (`0x0C3833E8`): 0 Original, 1 Maniac, 2 God.
- `meter.s` also has `score_hook`: the item-pickup score add `0x0C06B120(r4, points)` (literal `0x0C0951A0`) pays a flat 30000 while the x counter (`@(168, r4)`, cap 30000) is at the cap, in ARRANGE MODE only.
- `hyper.s` cash out: when `hyper_blast` runs with the x counter (`@(168, r4)`) at 30000 it cancels into gem type 3, lowers the counter by 25% and sets a 600 frame window (`0x0C7BFF2C`) in which `score_hook` still pays 30000 per pickup; `player_hook` counts the window down.
- `modesel.s` - Mode Select auto-walk: the six accessor literals in the state-4 input code (`0x0C104404/08/0C`, `0x0C104570/74/78`; accessors `0x0C05CA48` released, `0x0C05CA30` pressed, `0x0C05CA18` held) point to wrappers. In ARRANGE MODE they return nothing for the buttons and give a fake held Down while the cursor (`0x0C519B2C+0x18`) is below GOD, once time left R = seconds_left*60 + frame counter is <= 92 (the screen confirms at R about 60), then a second Down 8 frames later after clearing the game's move lock (`0x0C519B90`, `+0x14`). ORIGINAL ARCADE jumps to the real accessors.
- `stub.s` - tiny ROM stub in the free tail of u4 (file offset `0x1F8000`); the u4 header entry (`0x1C4`) points to it. It copies the patch to RAM `0x0C7C0000`.
- `build.py` - builds the patched u4 from your own `futariblj.zip`.
- `update_patchers.py` - embeds the changed bytes into `futari_patch.py`, `index.html` and the `.mra`.

Build 13 gives `futariarr_u4` CRC `2995da75`.

Notes: a PC-relative `mov.l` must not sit in a branch delay slot (illegal on real SH-3). The yellow tint word is `0x80FFFF00` (neutral is `0x80808080`).

- `p2off.s` - 2P off: the main loop calls the input poll `0x0C05C55C` through the literal `0x0C062F80`; in ARRANGE MODE `p2_hook` runs the poll and then zeroes the P2 input struct (`0x0C05C4AC` +12 held, +16 pressed, +20 released). A runtime change of the literal inside the poll does not work in MAME (the DRC does not see changes to code literals), so the hook is installed at boot.
